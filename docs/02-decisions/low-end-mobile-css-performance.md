# 저사양 모바일 기기를 위한 CSS 성능 분석 및 개선 방향
(CSS Performance Analysis for Low-End Mobile Devices)

이 문서는 AAKorea 프로젝트의 현재 CSS 시스템이 저사양 모바일 기기(예: 갤럭시 A 시리즈, Helio G99 등) 및 구형 브라우저 환경에서 발생시킬 수 있는 성능 문제를 분석하고, 이를 개선하기 위한 기술적 가이드라인을 제시합니다.

---

## 1. 주요 발견 사항 및 위험 요소 (Key Risks)

### 1-1. 고부하 렌더링 효과 (`backdrop-filter`)
*   **현황**: `MeetingFocusDialog` 오버레이(`16px`), 모바일 하단 푸터(`10px`), 스티키 헤더 등에 블러 효과 대거 적용.
*   **문제점**: 저사양 GPU(예: Mali-G57) 환경에서 배경 픽셀을 실시간으로 흐리게 처리하는 연산은 프레임 드랍(Jank)의 주원인입니다.
*   **결과**: 모달이 열리는 애니메이션이 부자연스럽고, 지도를 조작할 때 화면 반응 속도가 현저히 저하됩니다.

### 1-2. 페인팅 스트레스 (Heavy Shadows & Gradients)
*   **현황**: 최대 `90px` 반경의 대형 그림자(`--public-dialog-shadow`)와 다중 그래디언트 배경 사용.
*   **문제점**: 넓은 확산 범위를 가진 그림자는 브라우저가 그려야 할 페인팅 영역을 기하급수적으로 늘립니다. 리스트 스크롤 시 상시적인 페인팅 부하를 유발합니다.

### 1-3. 브라우저 호환성 결함 (`color-mix`)
*   **현황**: 버튼 배경 및 그림자 색상 연산에 `color-mix(in srgb, ...)` 사용.
*   **문제점**: **삼성 브라우저 14.0(Chromium 87)** 및 **iOS Safari 14.5** 이하 버전에서는 해당 함수를 인식하지 못합니다.
*   **결과**: 구형 기기에서 핵심 버튼의 배경색이 투명하게 나오거나 UI가 깨지는 치명적인 버그가 발생할 수 있습니다.

### 1-4. 레이아웃 재계산 (Reflow)
*   **현황**: `background`, `grid-template-rows` 등 레이아웃에 영향을 주는 속성에 `transition` 적용.
*   **문제점**: `transform`과 달리 이러한 속성들은 애니메이션 중 매 프레임 레이아웃 트리를 다시 계산하게 하여 CPU 점유율을 높입니다.

## 2. 하드웨어 타겟팅 분석 (Helio G99 & 6G RAM 기준)

| 하드웨어 항목 | 성능 영향도 | 분석 결과 |
| :--- | :---: | :--- |
| **GPU (Mali-G57)** | **상** | 블러(`backdrop-filter`)와 지도(Canvas) 동시 노출 시 처리 불능 수준의 성능 저하 우려. |
| **CPU (A76/A55)** | **중** | 복잡한 `calc()` 연산 및 리플로우 발생 애니메이션 시 미세한 스크롤 튐 발생 가능. |
| **RAM (6GB)** | **저** | 현재 앱 규모에서 메모리 부족으로 인한 문제는 거의 없으며, 멀티태스킹은 안정적임. |

## 3. 설계 원칙: 속도 우선 (Performance First)

AAKorea는 보급형 기기 사용자의 원활한 접근성을 위해 **'속도 우선 모드(Performance Mode)'를 서비스의 기본값(Default)**으로 설정합니다. 유려한 시각 효과는 조건부로 활성화되는 '추가 레이어'로 취급합니다.

### 3-1. [기본 설정] 고속/절전 모드 (Performance Mode)
*   **CSS 변수 기본값**: 블러 효과 (`0px`), 심플한 그림자, 최소한의 애니메이션을 `:root`의 기본값으로 정의합니다.
*   **효과**: 모든 기기에서 첫 접속 시 즉각적인 반응성과 부드러운 스크롤을 보장합니다.

### 3-2. [선택 적용] 프리미엄 UI (Rich UI)
*   **활성화 조건**: 하이엔드 기기로 판별되거나 사용자가 설정을 통해 직접 활성화한 경우에만 `.is-rich-ui` 클래스를 부여합니다.
*   **적용 효과**: `16px` 이상의 블러 효과, 대형 그림자, 고해상도 그래디언트 등 프리미엄 감성을 위한 요소를 추가합니다.

---

## 4. 기기 성능에 따른 동적 제어 전략 (Dynamic Control Strategy)

### 4-1. 자동 감지 및 Opt-in 패턴
사용자의 하드웨어를 감지하여 사양이 충분할 때만 'Rich UI'를 제안하거나 자동 활성화합니다.
*   **판단 기준**: RAM 4GB 이상 AND CPU 8코어 이상인 경우에만 프리미엄 레이어 고려.
*   **시스템 구조**: 
    1.  기본 CSS 로드 (Performance Mode).
    2.  JS로 하드웨어 사양 체크.
    3.  사양이 충분하면 `<html>`에 `.is-rich-ui` 클래스 추가 (선택적 전환).

### 4-2. 사용자 제어 인터페이스 (Settings)
사용자가 직접 '유려한 화면' 혹은 '빠른 속도'를 선택할 수 있는 설정 메뉴를 제공하여, 시스템 자동 감지의 오차를 보완하고 사용자 선택권을 존중합니다.

---

## 5. 기대 효과
*   **저사양 사용자 최우선 배려**: 별도의 설정 없이도 최적의 속도로 서비스 이용 가능.
*   **안정적인 하위 호환성**: 최신 CSS 기능(`color-mix`, `blur` 등)이 없어도 서비스 핵심 기능 이용에 차질 없음.
*   **배터리 효율 극대화**: 모바일 환경에서 불필요한 GPU 연산을 원천 차단하여 지속 가능한 서비스 제공.
