## 1. 진입점 및 부트스트랩 (Entry Point)
공개용 화면은 `index.html` → `src/public-main.jsx`를 통해 독립적으로 부트스트랩됩니다.

- **독립성**: 관리자 도메인과 물리적으로 분리되어 있어, 관리자 기능과 연관된 라이브러리(리치 텍스트 에디터 등)가 로드되지 않습니다.
- **핵심 진입점**: `src/public/app/PublicApp.jsx`가 레이아웃과 전역 상태(테마 등)를 관리합니다.

## 2. 핵심 사용자 흐름
공개 화면은 크게 **뉴스(공지사항)/콘텐츠 정보** 조회와 **모임 찾기**라는 두 가지 핵심 흐름을 가집니다.

- `/`: 메인 홈. 최신 공지 및 주요 링크 구성.
- `/meetings`: 상태 머신 기반의 지능형 모임 검색.
- `/content-pages/:key`: 백엔드 DB의 메타데이터와 파일 시스템의 HTML을 결합한 하이브리드 콘텐츠 렌더링.

## 2. 모임 검색 시스템 (Search Logic)

모임 찾기 기능은 복잡한 필터링 조건을 효율적으로 관리하기 위해 **상태 머신(`useMeetingSearch`)** 패턴을 따릅니다.

### 검색 상태 (States)
- **`IDLE`**: 초기 진입 상태. 검색 가이드라인을 노출합니다.
- **`LOADING`**: API 호출 및 데이터 로딩 중.
- **`REGION_ACTIVE`**: 특정 지역 기반 검색 결과가 표시 중인 상태.
- **`NEARBY_ACTIVE`**: 사용자 현재 위치 기반 거리순 검색 결과 상태.

### 데이터 처리 방식
1. **Lazy Fetching**: 사용자가 지역을 선택하거나 위치 검색 버튼을 누를 때만 대량의 데이터를 로드합니다.
2. **Memory Filtering**: 한 번 로드된 데이터(`rawMeetings`)는 클라이언트 가용 메모리에 유지되며, 이후의 세부 필터링(요일, 유형, 키워드)은 백엔드 요청 없이 즉시 처리됩니다.
3. **상태 잠금**: 검색이 활성화된 상태에서는 실수를 방지하기 위해 메인 지역 선택 기능을 비활성화하며, '검색 초기화'를 통해 복구할 수 있습니다.

## 3. 상세 모달 및 콘텐츠 구조
검색 결과를 클릭하면 페이지 전환 없이 상세 정보를 담은 대형 모달이 열립니다.

- **데이터 계층**: 그룹(Group) 정보 안에 소속된 여러 모임(Meetings) 리스트가 포함됩니다.
- **동적 렌더링**: 선택된 모임에 따라 지도 위치(`latitude`, `longitude` 기반)와 연락처 정보가 실시간으로 동기화됩니다.
- **애니메이션**: 부드러운 진입 효과(`entry-animation`)를 통해 사용자 경험을 향상합니다.
