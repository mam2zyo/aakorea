# ContentPage

## 이 문서의 역할

이 문서는 `ContentPage`의 현재 모델 의미와 필드를 정리한다.

이 문서에 포함하지 않는 내용:

- 제품 범위 판단
- 사용자 행동 흐름
- API 요청 / 응답 JSON 상세
- `Notice`와의 비교 기준 전체 설명

---

## 현재 모델 의미

`ContentPage`는 비교적 안정적인 설명 / 안내 정보를 담는 콘텐츠 모델이다.

현재 MVP에서 `ContentPage`는 아래 성격을 가진다.

- 시간에 민감하지 않다
- 공지보다 설명 / 안내 성격이 강하다
- 독립된 페이지 단위로 읽히는 것이 자연스럽다
- 누적 게시보다 유지 / 수정이 더 중요하다

---

## 현재 핵심 필드

- `id`
- `key`
- `title`
- `body`
- `published`

### 필드 메모

- `key`는 필수이며 고유해야 한다
- `title`, `body`는 필수다
- `published=false`면 공개 API에 노출되지 않는다

---

## 현재 규칙

- 운영자는 제목과 본문 중심으로 관리한다
- 공개 화면은 `published=true`인 페이지만 조회한다
- 대표 예시는 “처음 오신 분 안내” 같은 정적 페이지다

---

## 공개 흐름에서의 의미

- 홈과 공개 내비게이션에서 연결되는 안내 페이지의 본문 소스다
- 단건 페이지 조회 중심으로 사용한다

---

## 운영 흐름에서의 의미

- 운영자는 목록 / 상세 / 생성 / 수정 / 삭제를 수행한다
- 공지와 달리 최신순 누적보다 개별 페이지 유지가 중심이다

---

## 관계

- `Notice`와 함께 공개 콘텐츠를 구성하지만,
  `ContentPage`는 비교적 안정적인 설명 정보를 담당한다

---

## 제외 / 보류

현재는 아래를 지원하지 않는다.

- 범용 CMS 카테고리 구조
- FAQ 전용 모델
- 첨부파일 / 미디어 자산
