# DOMAIN_MODEL

## 이 문서의 역할

이 문서는 AAKorea Main 웹앱의 **현재 구현 기준 도메인 경계**를 정리한다.

이 문서가 답하는 질문:

- 지금 어떤 개체를 핵심 도메인으로 본다?
- 각 개체는 무엇을 소유하는가?
- 공개 흐름과 운영 흐름에서 각 개체는 어떤 역할을 갖는가?
- 최근 논의로 확정된 모델 축소/정리 방향은 무엇인가?

---

## 현재 핵심 도메인

현재 MVP의 핵심 도메인은 아래와 같다.

- `District`
- `Group`
- `GroupContact`
- `Meeting`
- `ContentPage`
- `Notice`

값 타입으로 다루는 항목:

- `Province`
- `DayOfWeek`
- `MeetingType`

---

## 1. District

`District`는 **지역연합**이다.

현재 구현에서 `District`는 아래 역할을 가진다.

- 그룹의 소속 기준
- 운영 목록과 정렬의 상위 기준
- 공개 화면에서 그룹의 지역연합 이름 표시

`District`는 아직 트리 구조나 상하위 조직 모델을 갖지 않는다.

---

## 2. Group

`Group`은 현재 시스템에서 **운영의 중심 단위**이자, 공개 화면에서 **모임들을 묶는 바깥 문맥**이다.

현재 구현에서 `Group`은 아래 의미를 가진다.

- 운영자가 생성/수정/삭제하는 실질 관리 단위
- `Meeting`, `GroupContact`가 속하는 상위 단위
- 공개 모임 상세 모달에서 제목과 지역연합 문맥을 제공하는 단위

### Group이 현재 직접 가지는 핵심 정보

- `name`
- `district`

### Group이 현재 핵심 필드로 채택하지 않는 정보

아래 항목은 이번 구조 정리에서 `Group` 핵심 필드에서 제외했다.

- `introduction`
- `notice`
- `changeSummary`
- 위치 정보

즉, 그룹 소개/그룹 공지/변경요약은 현재 MVP 범위에서 제외하고,
필요 시 나중에 성격을 다시 나눠 도입한다.

---

## 3. GroupContact

`GroupContact`는 `Group`에 연결된 **대표 연락처**다.

도메인적으로는 연락 지점 개체지만, 현재 구현과 운영 UX는 아래 기준을 따른다.

- 그룹당 대표 연락처 1건만 관리한다
- 현재 저장 필드는 `phone` 하나다
- 공개 화면에서는 이 번호를 전화 연결에 사용한다

### 현재 구현 메모

- 백엔드 생성 로직은 그룹당 연락처가 이미 있으면 `409 Conflict`를 반환한다
- 공개 API는 현재 `id` 오름차순 첫 연락처를 대표 번호로 사용한다
- 관리자 화면의 `email`, `우편수신주소`는 **목업 비활성 필드**이며 아직 저장되지 않는다

따라서 현재 도메인 문맥에서는 `GroupContact`를 “복수 연락처 목록”보다
**대표 연락처 1건**으로 이해하는 편이 정확하다.

---

## 4. Meeting

`Meeting`은 공개 탐색의 시작점이며, 동시에 **장소와 일정의 실제 소유자**다.

현재 구현에서 `Meeting`은 아래를 직접 가진다.

- `province`
- `locationName`
- `locationAddress`
- `dayOfWeek`
- `startTime`
- `type`
- `active`

### 현재 확정된 해석

- 사용자는 `Meeting` 목록으로 탐색을 시작한다
- 공개 상세는 그룹 문맥으로 보여 주지만, 실제 장소는 선택된 `Meeting` 기준으로 바뀐다
- “그룹 장소”보다 “모임 장소”가 실제 운영 언어에 가깝기 때문에, 위치 정보는 `Meeting`에 둔다

### Meeting 상태

- `active=true`: 공개 탐색에 노출되는 진행중 모임
- `active=false`: 잠정 중단 등으로 공개 목록에서 숨기는 모임

관리자 UI 기준으로는:

- 새 모임 추가 시 기본값은 `active=true`
- 모임 수정 시에만 상태 토글을 노출한다

### MeetingType

현재 허용값:

- `OPEN`
- `CLOSED`
- `NOTFIXED`

`NOTFIXED`는 단일한 공개/비공개로 설명하기 어려운 경우를 위한 완충값이다.

---

## 5. 공개 흐름에서의 도메인 해석

현재 공개 흐름은 아래처럼 이해하는 것이 가장 자연스럽다.

- 검색 시작점: `Meeting`
- 상세 문맥: `Group`
- 연락 연결: `GroupContact`

즉, **사용자는 모임을 찾고, 그룹 맥락 안에서 세부 장소와 연락처를 확인한다.**

현재 프론트 구현은 `/meetings` 페이지 안에서 같은 흐름을 유지한다.

- 목록에서 모임을 선택한다
- 같은 페이지 위에 상세 모달이 열린다
- 모달은 그룹명, 지역연합, 연락처, 모임 리스트를 보여 준다
- 리스트에서 다른 모임을 고르면 장소 정보가 바뀐다

---

## 6. 운영 흐름에서의 도메인 해석

운영 기준 중심 단위는 `Group`이다.

현재 운영 UI는 아래 구조를 따른다.

- 그룹 목록이 메인 진입점이다
- 그룹 생성은 2단계 큰 모달이다
- 그룹 수정은 읽기 중심 카드형 모달이다
- 기본 정보 / 연락처 / 모임 정보는 메인 모달에서 요약만 보여 준다
- 실제 수정은 각 섹션의 서브 모달에서 진행한다

즉, 현재 운영 UX는 “작업공간”보다 **목록 + 문서형 모달 + 서브 모달** 구조다.

---

## 개체 간 관계

### District -> Group

- 하나의 `District`는 여러 `Group`을 가진다

### Group -> GroupContact

- 현재 구현 기준으로 하나의 `Group`은 대표 연락처 1건을 가진다

### Group -> Meeting

- 하나의 `Group`은 여러 `Meeting`을 가진다
- 모임 추가 시 같은 그룹의 기존 장소를 기본값으로 제안하는 UX를 사용한다

---

## 현재 제외하거나 보류한 항목

아래 항목은 논의되었지만 아직 현재 도메인 핵심 필드로 채택하지 않았다.

- 그룹 소개
- 그룹 공지
- 그룹 변경 이력
- 이메일 저장
- 우편수신주소 저장
- 주소 검색 API 연동
- 지도 API 실제 연동

현재 문서 기준으로 이 항목들은 **향후 확장 후보**이며,
현재 구현은 전화번호와 모임 장소/일정 중심으로 유지한다.
