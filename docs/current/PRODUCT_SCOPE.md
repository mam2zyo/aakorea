# PRODUCT_SCOPE

## 이 문서의 역할

이 문서는 현재 MVP 범위를 **실제 구현과 최근 결정 기준**으로 다시 정리한다.

---

## 현재 MVP의 핵심 목표

현재 MVP의 목표는 아래 한 문장으로 정리할 수 있다.

> 사용자가 지역 기준으로 모임을 찾고, 그룹 문맥 안에서 장소와 연락처를 확인해 실제 연락까지 이어지게 한다.

---

## 현재 포함 범위

### 1. 공개 사용자 흐름

- 홈, 안내 페이지, 공지 조회
- 지역 기준 모임 검색
- `/meetings` 안에서 모임 상세 모달 조회
- 같은 그룹의 다른 모임 리스트 확인
- 선택된 모임 기준 장소 확인
- 대표 연락처 전화 연결

### 2. 운영자 흐름

- 로그인 / 로그아웃 / 세션 확인
- 지역연합 관리
- 그룹 관리
- 연락처 관리
- 모임 관리
- 콘텐츠 / 공지 관리

### 3. 관리자 UX 범위

- 그룹 목록 중심 진입
- 그룹 생성 2단계 모달
- 그룹 수정 메인 모달 + 섹션별 서브 모달
- 모임 추가 / 수정 / 삭제

---

## 현재 범위에서 명확히 제외한 것

### 그룹 콘텐츠 확장

아래 항목은 지금 단계에서 제외한다.

- 그룹 소개
- 그룹 공지
- 그룹 변경 이력

이 항목들은 필요가 없어서가 아니라,
나중에 어떤 형태가 맞는지 다시 나눠서 넣는 편이 더 낫다고 판단했다.

### 연락처 확장 저장

아래 항목은 아직 저장하지 않는다.

- 이메일
- 우편수신주소

현재 관리자 화면에는 목업으로만 노출한다.

### 지도 / 주소 고도화

아래 항목은 아직 준비 단계다.

- 주소 검색 API 실제 연동
- 지도 API 실제 연동
- 주소 기반 `province` 자동 저장

### 운영 확장 메뉴

아직 실제 기능 범위에 포함하지 않는다.

- 온라인 모임 관리
- 제12단계 운동 관리

---

## 현재 확정된 주요 제품 판단

### 1. 위치 정보는 모임에 둔다

실제 운영 언어도 “그룹 장소”보다 “모임 장소”에 가깝기 때문에,
위치의 소유권은 `Meeting`이 가진다.

### 2. 연락처는 현재 그룹당 1건으로 본다

현재 구현과 운영 UX는 대표 연락처 1건을 기준으로 한다.

### 3. 공개 상세는 별도 상세 페이지보다 검색 페이지 모달을 사용한다

현재는 검색 흐름을 끊지 않는 것이 더 중요하다고 판단했다.

### 4. 관리자 그룹 화면은 작업공간보다 문서형 편집 모달이 더 적합하다

현재는 목록 화면에서 빠르게 진입하고,
메인 모달은 읽기 중심, 실제 수정은 서브 모달에서 수행한다.
