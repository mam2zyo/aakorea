# PRODUCT_SCOPE

## 이 문서의 역할

이 문서는 AAKorea Main 웹앱의 현재 MVP 범위를 정의한다.

이 문서가 답하는 질문:

- 현재 MVP에서 무엇을 만든다?
- 현재 MVP에서 무엇을 만들지 않는다?
- 포함 여부를 어떤 기준으로 판단한다?

이 문서에 포함하지 않는 내용:

- 사용자별 상세 행동과 시나리오
- 도메인 모델의 상세 구조와 관계 설명
- 엔티티별 최소 필드 정의
- API 요청/응답 계약
- 구현 단계별 작업 순서

---

## 프로젝트 목표

이 프로젝트의 현재 목표는 **처음 방문한 사람이 지역별 모임을 찾고, 적절한 연락처로 연결될 수 있는 최소한의 웹 경험**을 제공하는 것이다.

즉, 현재 MVP는 다음 문제를 해결하는 데 집중한다.

- 처음 온 사용자가 어디서 도움을 받을 수 있는지 빠르게 이해할 수 있어야 한다
- 사용자가 자신의 지역에 맞는 모임을 찾을 수 있어야 한다
- 사용자가 모임 또는 그룹에 연락할 수 있어야 한다
- 운영자가 이 최소 정보를 직접 관리할 수 있어야 한다

---

## MVP 핵심 가치

현재 MVP의 핵심 가치는 다음 한 문장으로 정리한다.

> 사용자가 지역 기준으로 모임을 찾고, 연락 가능한 지점까지 도달하게 한다.

이 기준에서 현재 가장 중요한 공개 기능은 다음 두 가지다.

- `Province` 기준으로 `Meeting`을 탐색할 수 있어야 한다
- 모임 상세에서 유효한 연락처로 연결될 수 있어야 한다

운영 기능은 이 공개 흐름을 유지하기 위한 최소 범위까지만 포함한다.

---

## 현재 포함 범위

현재 MVP에는 아래 범위를 포함한다.

### 1. 공개 정보 탐색

- 서비스 소개 및 기본 안내
- 처음 방문한 사람을 위한 정적 정보 제공
- 공지성 정보 제공
- 지역별 모임 탐색
- 모임 상세 정보 조회
- 연락 가능한 전화번호 확인

### 2. 운영 대상 데이터 관리

- `District` 관리
- `Group` 관리
- `GroupContact` 관리
- `Meeting` 관리
- `ContentPage` 관리
- `Notice` 관리

### 3. 운영 접근

- 운영자 로그인
- 인증된 운영자의 최소 관리 기능 접근

### 4. 최소한의 공개-운영 연결

- 운영자가 입력한 정보가 공개 화면에 반영된다
- 공개 화면은 운영 데이터 중 필요한 최소 정보만 노출한다

---

## 현재 MVP의 핵심 포함 항목

현재 단계에서 반드시 살아 있어야 하는 항목은 다음과 같다.

### 공개 측면

- 지역 기준 모임 조회
- 모임의 기본 정보 확인
- 그룹 또는 모임과 연결 가능한 연락처 확인

### 운영 측면

- 지역/그룹/연락처/모임 데이터 관리
- 공개용 정적 페이지와 공지 관리
- 운영 로그인

이 항목들은 다른 기능보다 우선한다.

---

## 현재 제외 범위

아래 항목은 현재 MVP 범위에 포함하지 않는다.

### 1. 일반 사용자 계정 기능

- 회원가입
- 일반 사용자 로그인
- 마이페이지
- 개인화 기능

### 2. 복잡한 권한 체계

- 다단계 승인
- 역할별 세분 권한
- 복잡한 편집 권한 분기
- 조직별 정교한 접근 제어

### 3. 확장 도메인

- `Committee`
- `Conference`
- 독립적인 행사/이벤트 확장 모델
- 복잡한 조직 트리 확장
- 온라인 모임 관리 전용 운영 도메인
- 제12단계 운동 관리 전용 운영 도메인

### 4. 게시판형 확장

- 범용 게시판
- 게시글/댓글 중심 구조
- 커뮤니티 상호작용 기능

### 5. 첨부파일 및 미디어 고도화

- 파일 라이브러리
- 이미지/첨부파일 관리 고도화
- 미디어 중심 콘텐츠 편집 기능

### 6. 고급 사용자 기능

- 고급 검색
- 추천
- 즐겨찾기
- 알림
- 개인화된 탐색 흐름

## 현재 보류하는 판단

현재 MVP에서는 다음과 같은 판단을 유지한다.

### 1. 운영 복잡성보다 공개 탐색 가치를 우선한다

운영 기능은 필요하지만, 운영 기능 자체의 복잡도를 늘리는 것보다 공개 탐색 흐름을 먼저 완성한다.

### 2. 도메인 확장보다 핵심 흐름 완성을 우선한다

범용 게시판 등은 확장 가능성이 있지만, 현재는 도입하지 않는다.

### 3. 풍부한 기능보다 정확한 최소 정보 제공을 우선한다

지금은 많은 정보를 보여주는 것보다, 사용자가 실제로 도움이 되는 정보에 도달하는 것이 더 중요하다.

### 4. 일반 사용자 기능보다 운영 입력과 공개 노출의 연결을 우선한다

현재 MVP에서는 운영자가 입력한 정보가 공개 탐색에 안정적으로 연결되는 것이 더 중요하다.

### 5. 운영 메뉴는 확장 가능하게 두되, 초기에는 핵심 관리 흐름을 우선한다

향후 운영 메뉴에 온라인 모임 관리, 제12단계 운동 관리가 추가될 가능성이 있다.  
다만 현재 단계에서는 운영 정보 구조와 레이아웃만 이를 수용 가능하게 준비하고,  
실제 도메인 구현과 화면 추가는 후속 단계로 보류한다.

---

## 범위 판단 기준

새로운 기능이나 개체를 MVP에 넣을지 판단할 때는 아래 기준을 사용한다.

### 포함하는 경우

아래 중 하나 이상에 직접적으로 기여하면 포함을 검토한다.

- 사용자가 지역별 모임을 더 정확히 찾는 데 필요하다
- 사용자가 실제 연락 가능한 지점에 도달하는 데 필요하다
- 운영자가 핵심 공개 정보를 유지·수정하는 데 필요하다
- MVP 핵심 흐름을 성립시키는 데 필수적이다

### 제외하거나 보류하는 경우

아래에 해당하면 현재는 보류한다.

- 없어도 핵심 탐색/연락 흐름이 성립한다
- 운영 편의만 높이고 공개 가치에는 직접 기여하지 않는다
- 모델 복잡도나 권한 복잡도를 크게 올린다
- 이후 확장 단계에서 분리 가능한 기능이다

---

## 현재 MVP의 제품 경계

현재 MVP를 한 문장으로 설명하면 다음과 같다.

> AAKorea의 공개 정보 제공과 지역별 모임 탐색, 그리고 그 정보를 유지하기 위한 최소 운영 기능을 제공하는 웹앱
