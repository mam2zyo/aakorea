# ACTORS_AND_USE_CASES

## 이 문서의 역할

이 문서는 AAKorea Main 웹앱의 현재 MVP에서 **누가 어떤 목표로 어떤 행동을 하는지** 정의한다.

이 문서가 답하는 질문:

- 현재 주요 사용자는 누구인가?
- 각 사용자의 핵심 목표는 무엇인가?
- 어떤 유스케이스가 MVP에 포함되는가?

이 문서에 포함하지 않는 내용:

- 무엇을 포함하고 제외하는지에 대한 제품 범위 판단
- 도메인 모델의 상세 구조와 관계 정의
- 엔티티별 최소 필드 정의
- API 요청/응답 계약
- 구현 단계별 작업 순서

---

## 현재 주요 액터

현재 MVP에서 다루는 주요 액터는 아래 두 종류다.

1. 공개 사용자인 **방문자**
2. 인증된 **운영자**

현재 MVP는 일반 사용자 회원 체계를 다루지 않으므로,  
방문자는 로그인하지 않은 공개 사용자로 본다.

---

## 액터 1. 방문자

### 정의

방문자는 AAKorea 웹앱에 처음 오거나, 공개 정보만 이용하는 사용자다.

이 액터에는 다음과 같은 사람이 포함될 수 있다.

- 도움이나 모임 정보를 찾는 사람
- 가족 또는 지인
- 정보를 대신 찾아보는 사람
- 공지나 안내를 확인하려는 사람

이 문서에서는 이들을 세부적으로 더 나누지 않고,  
**공개 정보를 탐색하는 사용자**라는 공통 행동 기준으로 다룬다.

### 핵심 목표

방문자의 핵심 목표는 다음과 같다.

- 서비스의 기본 목적을 이해한다
- 필요한 안내 정보를 찾는다
- 자신의 지역에 맞는 모임을 찾는다
- 연락 가능한 지점을 확인한다

### MVP에서의 핵심 성공 조건

방문자는 복잡한 탐색 없이 다음에 도달할 수 있어야 한다.

- 지역 기준 모임 목록
- 모임 기본 정보
- 연락 가능한 전화번호

---

## 액터 2. 운영자

### 정의

운영자는 인증 후 시스템에 접속하여 공개 정보를 관리하는 사용자다.

현재 MVP에서 운영자는 **복잡한 권한 분기 없이**,  
핵심 공개 정보를 입력·수정·관리하는 역할로 본다.

### 핵심 목표

운영자의 핵심 목표는 다음과 같다.

- 공개 사이트에 필요한 핵심 정보를 관리한다
- 지역/그룹/모임 정보를 최신 상태로 유지한다
- 안내성 콘텐츠와 공지를 게시한다
- 공개 화면에 노출될 정보를 안정적으로 운영한다

### MVP에서의 핵심 성공 조건

운영자는 최소한 다음 작업을 할 수 있어야 한다.

- 로그인
- 조직 및 모임 정보 등록/수정
- 정적 안내 콘텐츠 관리
- 공지 등록/수정

---

## 유스케이스 목록

아래 유스케이스는 현재 MVP 기준으로 정리한다.

우선순위 구분:

- **필수**: MVP에 반드시 포함
- **선택**: 있으면 좋지만 현재 MVP 필수는 아님
- **보류**: 이후 단계 검토

---

## 방문자 유스케이스

### V-01. 서비스의 기본 목적을 이해한다

- 액터: 방문자
- 우선순위: 필수
- 설명: 방문자는 공개 페이지를 통해 서비스가 무엇을 위한 것인지 이해한다.
- 기대 결과: 서비스 소개, 안내성 콘텐츠, 기본 구조를 파악할 수 있다.

### V-02. 처음 방문한 사람을 위한 안내 정보를 확인한다

- 액터: 방문자
- 우선순위: 필수
- 설명: 방문자는 처음 온 사람에게 필요한 기본 설명과 안내를 읽는다.
- 기대 결과: 다음 행동으로 무엇을 해야 하는지 이해할 수 있다.

### V-03. 공지성 정보를 확인한다

- 액터: 방문자
- 우선순위: 필수
- 설명: 방문자는 공개된 공지 또는 최신 안내 정보를 확인한다.
- 기대 결과: 중요한 변경사항이나 안내를 놓치지 않는다.

### V-04. 지역 기준으로 모임을 찾는다

- 액터: 방문자
- 우선순위: 필수
- 설명: 방문자는 자신의 지역에 맞는 모임을 조회한다.
- 기대 결과: 적절한 모임 목록에 도달한다.

### V-05. 모임 상세 정보를 확인한다

- 액터: 방문자
- 우선순위: 필수
- 설명: 방문자는 목록에서 선택한 모임의 기본 정보를 확인한다.
- 기대 결과: 해당 모임이 어떤 모임인지 이해한다.

### V-06. 연락 가능한 전화번호를 확인한다

- 액터: 방문자
- 우선순위: 필수
- 설명: 방문자는 모임 또는 그룹에 연락 가능한 번호를 확인한다.
- 기대 결과: 실제 연락 행동으로 이어질 수 있다.

### V-07. 사이트 내에서 필요한 기본 콘텐츠를 탐색한다

- 액터: 방문자
- 우선순위: 선택
- 설명: 방문자는 소개, 안내, 정보성 콘텐츠를 탐색한다.
- 기대 결과: 필요한 정적 정보를 스스로 찾을 수 있다.

### V-08. 고급 검색 또는 필터를 사용한다

- 액터: 방문자
- 우선순위: 보류
- 설명: 방문자는 다양한 조건으로 모임을 정교하게 검색한다.
- 기대 결과: 더 복잡한 탐색이 가능하다.
- 비고: 현재 MVP의 직접 목표는 아니다.

### V-09. 개인 계정으로 저장/즐겨찾기를 사용한다

- 액터: 방문자
- 우선순위: 보류
- 설명: 방문자는 개인 계정을 기반으로 콘텐츠를 저장하거나 관리한다.
- 기대 결과: 개인화된 사용 경험을 얻는다.
- 비고: 현재 MVP 범위 밖이다.

## 운영자 유스케이스

### A-01. 운영자로 로그인한다

- 액터: 운영자
- 우선순위: 필수
- 설명: 운영자는 인증 후 관리 기능에 접근한다.
- 기대 결과: 공개 데이터 관리 기능을 사용할 수 있다.

### A-02. District 정보를 관리한다

- 액터: 운영자
- 우선순위: 필수
- 설명: 운영자는 운영 조직 기준이 되는 District 정보를 관리한다.
- 기대 결과: Group과 관련 데이터의 운영 기준이 유지된다.

### A-03. Group 정보를 관리한다

- 액터: 운영자
- 우선순위: 필수
- 설명: 운영자는 Group 기본 정보를 등록·수정한다.
- 기대 결과: 공개 및 운영에서 참조할 그룹 정보가 유지된다.

### A-04. GroupContact 정보를 관리한다

- 액터: 운영자
- 우선순위: 필수
- 설명: 운영자는 공개 연락에 필요한 연락처를 관리한다.
- 기대 결과: 방문자가 실제로 사용할 수 있는 연락처가 유지된다.

### A-05. Meeting 정보를 관리한다

- 액터: 운영자
- 우선순위: 필수
- 설명: 운영자는 공개 탐색 대상이 되는 모임 정보를 관리한다.
- 기대 결과: 지역별 모임 조회가 가능한 상태를 유지한다.

### A-06. MeetingPlace 정보를 관리한다

- 액터: 운영자
- 우선순위: 필수
- 설명: 모임의 필수 구성요소 중 하나인 위치 정보를 관리한다.
- 기대 결과: 방문자는 신뢰할 수 있는 위치 정보를 획득할 수 있다.

### A-07. ContentPage를 관리한다

- 액터: 운영자
- 우선순위: 필수
- 설명: 운영자는 소개, 안내, 정적 정보를 담는 콘텐츠를 관리한다.
- 기대 결과: 공개 사이트의 기본 안내 구조를 유지한다.

### A-08. Notice를 관리한다

- 액터: 운영자
- 우선순위: 필수
- 설명: 운영자는 공지성 정보를 등록·수정·노출 관리한다.
- 기대 결과: 공개 공지가 최신 상태로 유지된다.

### A-09. 공개 노출 결과를 확인한다

- 액터: 운영자
- 우선순위: 필수
- 설명: 운영자는 자신이 입력한 데이터가 공개 화면에 반영되는지 확인한다.
- 기대 결과: 운영 입력과 공개 노출 간 연결 상태를 검증할 수 있다.

### A-10. 세분화된 권한 체계로 운영자를 관리한다

- 액터: 운영자
- 우선순위: 보류
- 설명: 운영자는 역할별로 서로 다른 권한을 갖고 시스템을 사용한다.
- 기대 결과: 조직 구조에 맞는 정교한 운영이 가능하다.
- 비고: 현재 MVP 범위 밖이다.

### A-11. 첨부파일이나 미디어 자산을 관리한다

- 액터: 운영자
- 우선순위: 보류
- 설명: 운영자는 이미지, 파일, 미디어 자산을 체계적으로 업로드하고 재사용한다.
- 기대 결과: 콘텐츠 운영 효율이 높아진다.
- 비고: 현재 MVP 범위 밖이다.

## 핵심 사용자 흐름

현재 MVP에서 특히 중요한 흐름은 아래 두 가지다.

### 공개 핵심 흐름

1. 방문자가 사이트에 들어온다
2. 기본 안내 또는 소개를 본다
3. 지역 기준으로 모임을 찾는다
4. 모임 상세를 확인한다
5. 연락 가능한 번호를 확인한다

### 운영 핵심 흐름

1. 운영자가 로그인한다
2. District / Group / GroupContact / Meeting 정보를 관리한다
3. ContentPage / Notice를 관리한다
4. 공개 화면에서 반영 결과를 확인한다

이 두 흐름은 다른 유스케이스보다 우선한다.

- A-03 Group 관리

- A-05 Meeting 관리
