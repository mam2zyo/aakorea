# IMPLEMENTATION_PLAN

## 이 문서의 역할

이 문서는 초기 계획 문서라기보다, **현재까지 정리된 구현 상태와 다음 작업 메모**를 기록한다.

---

## 현재 완료된 큰 흐름

### 1. 기반 구조

- 공통 응답 형식
- 운영 인증
- 공개 / 운영 라우트 분리

### 2. 공개 흐름

- 홈 / 안내 / 공지 조회
- 지역 기준 모임 검색
- `/meetings` 안에서 같은 페이지 모달 상세
- 그룹 문맥 + 선택된 모임 포커스 표시
- 전화 걸기 연결

### 3. 운영 조직/그룹 흐름

- 지역연합 목록/생성/수정/삭제
- 그룹 목록/생성/수정/삭제
- 그룹당 대표 연락처 1건 관리
- 그룹 삭제 시 연결 모임/연락처 함께 삭제

### 4. 운영 모임 흐름

- 그룹 안에서 모임 생성
- 모임 수정
- 모임 삭제
- 모임 상태 토글

### 5. 운영 UI 정리

- 그룹 메인 진입은 목록
- 그룹 생성은 2단계 모달
- 그룹 수정은 읽기 중심 카드 모달
- 기본 정보 / 연락처 / 모임 정보는 서브 모달 편집

---

## 현재 구현 기준 상세 상태

### 그룹 생성

- 1단계: 그룹 이름, 지역연합, 연락처
- 2단계: 첫 모임 등록
- 새 모임 생성 기본 상태는 `active=true`

### 그룹 수정

- 메인 모달은 문서처럼 읽기 중심
- 기본 정보 / 연락처 / 모임 정보를 카드로 구분
- 각 섹션의 `수정`은 서브 모달로 분리

### 모임 수정

- 상단 필드 순서 통일:
  - 요일 / 시작 시간 / 모임 유형
  - 장소명 / 지역
  - 주소
- 상태는 수정 모달에서만 토글
- 새 모임 추가에서는 상태 UI를 숨기고 기본값 `true`

## 다음 우선 작업

### 1. 주소 검색 API 연동

- 주소 검색
- 우편번호 확보
- 주소 기반 `province` 자동 저장

### 2. 지도 API 연동

- 공개 모달 지도 영역
- 운영 모임 편집 지도 미리보기
- 저장된 `latitude`, `longitude` 활용

### 3. 좌표 저장 구조 정리

- `latitude`
- `longitude`
- 주소 변경 시 지오코딩 재시도 정책

### 4. 공개 상세 정교화

- 현재 `/meetings` 모달 흐름 유지
- 필요 시 `GET /api/public/meetings/{id}` 사용 위치 재정리

---

## 현재 구현 검증 기준

현재는 아래가 안정적으로 동작하면 핵심 흐름이 성립한다고 본다.

- 방문자가 지역별로 모임을 찾을 수 있다
- 방문자가 모달에서 장소와 연락처를 확인할 수 있다
- 운영자가 그룹과 모임을 생성/수정/삭제할 수 있다
- 운영자가 모임 상태를 잠정 중단으로 전환할 수 있다
- 그룹 삭제 시 고아 데이터가 남지 않는다
