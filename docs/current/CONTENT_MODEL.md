# CONTENT_MODEL

## 이 문서의 역할

이 문서는 AAKorea Main 웹앱의 현재 MVP에서 **콘텐츠성 정보를 어떤 모델로 구분해 다룰지** 정의한다.

이 문서가 답하는 질문:

- 어떤 정보를 `ContentPage`로 다루는가?
- 어떤 정보를 `Notice`로 다루는가?
- 어떤 콘텐츠 관련 개념을 현재 별도 모델로 두지 않는가?
- 콘텐츠 모델을 나누는 기준은 무엇인가?

이 문서에 포함하지 않는 내용:

- 제품 범위의 상세 판단
- 사용자별 목표와 행동 흐름
- 도메인 전체 구조와 관계 정의
- 엔티티별 최소 필드 목록
- API 요청/응답 계약
- 구현 단계별 작업 순서

---

## 현재 채택하는 콘텐츠 모델

현재 MVP에서 채택하는 콘텐츠 모델은 다음 두 가지다.

- `ContentPage`
- `Notice`

현재는 이 두 모델만으로 공개 사이트의 콘텐츠 요구를 충족하는 것을 목표로 한다.

즉, 현재 MVP에서는 공개 정보 영역을 크게 다음 두 성격으로 나눈다.

1. 비교적 안정적인 안내/설명 정보
2. 시의성 있는 공지/업데이트 정보

이 구분이 현재 콘텐츠 모델의 핵심이다.

---

## 1. ContentPage

### 정의

`ContentPage`는 비교적 안정적인 설명, 소개, 안내 정보를 담는 콘텐츠 모델이다.

### 현재 MVP에서의 역할

`ContentPage`는 다음과 같은 정보를 표현하는 데 사용한다.

- 서비스 소개
- 처음 방문한 사람을 위한 안내
- 일반적인 정보 제공 페이지
- 자주 바뀌지 않는 설명성 콘텐츠
- 구조적으로 독립된 정적 페이지

### 이 모델을 선택하는 기준

다음 조건에 해당하면 `ContentPage`로 다룬다.

- 시간에 민감하지 않다
- 공지나 업데이트보다 설명/안내 성격이 강하다
- 비교적 안정적으로 유지된다
- 독립된 페이지 단위로 제공하는 것이 자연스럽다
- 운영자가 본문 중심으로 관리하면 충분하다

### 이 모델에 기대하는 운영 방식

- 운영자가 제목과 본문 중심으로 관리한다
- 페이지 단위로 공개 노출된다
- 자주 누적되기보다, 유지·수정되는 성격이 강하다

### 대표 예시

- AAKorea 소개
- 처음 오신 분 안내
- 모임 참여 전 기본 안내
- 일반 정보성 설명 페이지

---

## 2. Notice

### 정의

`Notice`는 공개 사용자에게 전달해야 하는 공지성, 시의성, 업데이트성 정보를 담는 콘텐츠 모델이다.

### 현재 MVP에서의 역할

`Notice`는 다음과 같은 정보를 표현하는 데 사용한다.

- 운영 공지
- 최근 변경사항 안내
- 일정 기간 중요하게 노출할 정보
- 최신 안내성 메시지
- 시간 흐름에 따라 추가/교체되는 정보

### 이 모델을 선택하는 기준

다음 조건에 해당하면 `Notice`로 다룬다.

- 시의성이 있다
- 공지 또는 업데이트 성격이 강하다
- 최신순 또는 목록 노출이 자연스럽다
- 시간이 지나면 중요도가 낮아질 수 있다
- 설명 페이지보다 “알림”에 가깝다

### 이 모델에 기대하는 운영 방식

- 운영자가 공지 단위로 등록/수정한다
- 목록 또는 강조 영역으로 노출될 수 있다
- 누적 관리 또는 게시 이력이 의미를 가진다
- 공개 화면에서 최신 정보 전달 역할을 한다

### 대표 예시

- 사이트 운영 공지
- 임시 변경 안내
- 특정 기간 동안 중요한 안내
- 최근 업데이트 알림

## 경계 사례 판단 기준

실제 운영에서는 어떤 콘텐츠가 `ContentPage`인지 `Notice`인지 애매할 수 있다.  
그 경우 아래 질문 순서로 판단한다.

### 판단 질문 1

이 정보는 시간이 지나도 기본적으로 계속 유지되어야 하는가?

- 그렇다면 `ContentPage` 가능성이 높다
- 아니라면 `Notice` 가능성이 높다

### 판단 질문 2

이 정보는 “설명”인가, “공지”인가?

- 설명이면 `ContentPage`
- 공지이면 `Notice`

### 판단 질문 3

이 정보는 단독 페이지로 읽히는 것이 자연스러운가?

- 그렇다면 `ContentPage`
- 아니고 목록/최신순 노출이 자연스러우면 `Notice`

### 판단 질문 4

이 정보는 누적 게시 이력이 의미가 있는가?

- 그렇다면 `Notice`
- 아니라면 `ContentPage`

## 현재 별도 콘텐츠 모델로 두지 않는 것

현재 MVP에서는 아래 개념을 별도 콘텐츠 모델로 두지 않는다. 추후 프로젝트가 확장될 경우 포함될 가능성이 있다.

### 1. Board / Post

범용 게시판 구조는 현재 채택하지 않는다.

### 2. FAQ 전용 모델

자주 묻는 질문은 현재 별도 모델로 분리하지 않는다.

### 3. 카테고리화된 CMS 구조

범용 카테고리, 태그, 다중 콘텐츠 타입 중심의 CMS 구조는 현재 채택하지 않는다.

### 4. Attachment / MediaAsset

첨부파일, 이미지 라이브러리, 재사용 미디어 자산 모델은 현재 별도 채택하지 않는다.

### 5. Event / Campaign 콘텐츠 모델

행사, 캠페인 등 특수 목적 콘텐츠 모델은 현재 채택하지 않는다.

---

## 현재 콘텐츠 구조 요약

현재 MVP의 콘텐츠 구조는 다음처럼 요약할 수 있다.

- 안정적이고 설명 중심인 정보는 `ContentPage`
- 시의성이 있고 공지 중심인 정보는 `Notice`

이 두 모델만으로 현재 MVP의 공개 콘텐츠 요구를 우선 충족한다.  
그 밖의 콘텐츠 확장은 실제 운영 요구가 명확해진 이후에 검토한다.
