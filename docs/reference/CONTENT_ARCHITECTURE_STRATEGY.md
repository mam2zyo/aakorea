# 콘텐츠 아키텍처 전략: Refined HTML vs JSX

이 문서는 A.A. Korea 공개 사이트의 콘텐츠(안내 페이지, 도구 등)를 구현할 때 고려해야 할 기술적 접근 방식과 인터랙션 처리 전략을 정리합니다.

## 1. 개요
현재 `ContentPage` 시스템은 리치 텍스트 에디터를 통해 콘텐츠를 게시합니다. 하지만 복잡한 레이아웃이나 사용자 인터랙션이 필요한 콘텐츠(예: 44가지 질문 자가진단)의 경우, 에디터 방식의 한계를 극복하기 위해 **정제된 HTML(Refined HTML)** 또는 **JSX** 기반의 접근 방식이 필요합니다.

---

## 2. 접근 방식 비교

| 구분 | 정제된 HTML (Refined HTML) | JSX (React Component) |
| :--- | :--- | :--- |
| **적합한 콘텐츠** | 역사, 소개, FAQ 등 문서 위주 | 자가진단 퀴즈, 계산 도구, 지도 등 |
| **관리 방식** | DB 저장 (운영 도구에서 수정 가능) | 코드 관리 (개발자가 Git으로 관리) |
| **디자인 제어** | CSS 변수 및 앱 테마를 따르는 클래스 활용 | React 컴포넌트의 모든 UI 기능 활용 |
| **장점** | 유지보수 효율, 높은 데이터 접근성 | 무한한 확장성, 복잡한 상태 관리 가능 |

---

## 3. 디자인 및 테마 전략
외부에서 작성된 HTML을 입력받을 때 앱의 테마(다크 모드 등)와 충돌하지 않도록 다음 규칙을 준수합니다.

### CSS 변수(Variables) 연동
하드코딩된 색상 대신 앱의 시스템 변수를 사용합니다.
*   **Text**: `var(--color-text)`, `var(--color-text-muted)`
*   **Background**: `var(--public-panel-background)`
*   **Brand**: `var(--color-primary)`

### 모바일 친화적 구조
*   모든 요소에 `max-width: 100%`, `height: auto`를 강제하여 화면 깨짐 방지.
*   테이블(`<table>`)은 `overflow-x: auto` 컨테이너로 감싸 모바일 대응.

### 정제(Sanitization) 프로세스
*   업로드 시 `<script>`, `<style>`, `<link>` 등의 위험 태그 혹은 전역 스타일 오염 가능성이 있는 태그는 필터링하거나 제거합니다.

---

## 4. 인터랙션 처리 전략

### 단순 인터랙션 (HTML 기반)
HTML 본문 내에서 클릭 이벤트 등이 필요할 경우 **이벤트 위임(Event Delegation)** 방식을 사용합니다.
*   HTML 요소에 `data-action` 속성 부여.
*   부모 컨테이너(React)에서 클릭 시 해당 속성을 읽어 로직 실행.

### 복잡한 인터랙션 (JSX 기반)
상태 변화(State)와 복잡한 계산이 수반되는 도구는 별도의 **JSX 페이지 컴포넌트**로 정교하게 개발합니다.
*   관리의 편의를 위해 일반 문서(HTML)와 인터랙티브 앱(JSX)을 분리하여 제공하는 **하이브리드 전략**을 권장합니다.

---

## 5. 단계별 로드맵 (제안)
1.  **1단계**: 기존 `old_contents`의 HTML 파일들을 앱의 CSS 변수와 클래스 구조에 맞게 리팩토링(Refactoring).
2.  **2단계**: 백엔드에 HTML 파일을 직접 입력/업로드할 수 있는 파이프라인 구축.
3.  **3단계**: 자가진단 등 인터랙션이 핵심인 기능은 별도의 JSX 전용 페이지로 개발.
