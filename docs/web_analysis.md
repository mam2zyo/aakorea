# 웹(사용자용) 분석 보고서

## 1. 보안 분석

### [Low] CMS 컨텐츠의 XSS 방지
- **현황**: 애플리케이션은 `publicContentApi.getContentPage`를 통해 컨텐츠를 렌더링합니다.
- **위험**: "오피스" 관리자 패널에서 검증 없이 원본 HTML 입력을 허용하고, "웹" 프론트엔드에서 이를 `{@html ...}`로 렌더링할 경우 XSS 공격에 노출될 수 있습니다.
- **권장사항**: 백엔드에서 HTML을 새니타이징(Sanitization)하거나, 프론트엔드에서 렌더링 시 `dompurify` 같은 라이브러리를 사용하십시오.

---

## 2. 성능 분석

### [High] 클라이언트 사이드 내비게이션 시 이벤트 리스너 누수
- **위치**: `Header.svelte` (14-38행)
- **문제점**: `window.addEventListener('scroll', ...)`가 `onMount` 외부에서 등록되었습니다.
- **위험**: 레이아웃 컴포넌트라 유지되는 편이지만, 컴포넌트가 다시 마운트될 경우 리스너가 중복 등록되어 메모리 누수나 성능 저하를 일으킬 수 있습니다.
- **권장사항**: 스크롤 리스너 로직을 `onMount` 내부로 이동시키고, 리스너를 제거하는 클린업(Cleanup) 함수를 반환하도록 수정하십시오.



### [Low] 이미지 최적화
- **현황**: `@sveltejs/enhanced-img`를 사용하여 LCP와 성능을 잘 챙기고 있습니다.
- **개선안**: `static/` 디렉토리에 있는 정적 자산 중 용량이 큰 것들도 최적화되었는지 확인하십시오.

---

## 3. 버그 가능성 및 리팩토링

### [Refactoring] Svelte 5 Rune 마이그레이션
- **현황**: 이미 Svelte 5의 `$state`, `$derived` 등을 잘 활용하고 있습니다.
- **개선안**: `$lib` 내의 유틸리티들도 가능한 `.svelte.ts` 파일로 옮겨 보편적 반응성(Universal Reactivity)을 활용하도록 마이그레이션을 지속하십시오.

### [UX/Bug] 지오로케이션(Geolocation) 에러 처리
- **위치**: `meetings/+page.svelte` (62-92행)
- **현황**: 기본적인 성공/실패 사례를 처리하고 있습니다.
- **개선안**: 크롬 등 최신 브라우저는 HTTPS 환경에서만 지오로케이션을 지원합니다. 운영 환경이 HTTPS임을 보장하고, 사용자에게 권한 거부 시의 안내를 명확히 하십시오.

### [SEO] 메타 태그 최적화
- **위치**: `app.html` 및 `+page.svelte`
- **현황**: `app.html`에 기본 메타 태그가 설정되어 있습니다.
- **개선안**: 공지사항 상세 페이지 등 동적 라우트에서 `svelte:head`를 사용하여 페이지별 구체적인 제목과 OpenGraph 태그를 제공하면 소셜 공유 시 효과적입니다.
